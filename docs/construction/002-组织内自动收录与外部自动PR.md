# 002 · 组织内自动收录与外部自动 PR

日期：2026-11-02
状态：已完成

## 目标

按来源分层调整收录流程：`GQYTeam` 组织内公开插件自动进入 `registry.json`；组织外的在线 GitHub 仓库一律由自动化生成 PR，不直接写 main。

## 范围

**做：**

- 新增 `gqy-plugin sync-org`：列出组织内公开插件仓库，读取默认分支 HEAD，下载 commit-pinned tarball，校验 manifest / SHA-256 / size，写入目录。
- 新增 `gqy-plugin add-external`：解析插件收录 issue，校验外部 GitHub Release 产物，写入带 `source_type=external` 的候选条目。
- 新增 `sync-org-plugins.yml`：每 6 小时与手动触发，直接提交组织内收录结果。
- 新增 `external-plugin-pr.yml`：issue / 手动触发，验证后自动创建或更新 PR，不合并。
- 目录 schema 增加 `source_type` 与 `repository`。
- main 保护从经典 branch protection 迁移到 ruleset；保留人工评审和 CI 要求，将同步 bot 加入 bypass。
- 更新静态站、README、设计、蓝图和协议文档。

**不做：**

- 自动合并外部 PR。
- 为组织内插件自动生成 GitHub Release。
- 自动发现组织外的任意仓库；外部仓库必须通过 issue / dispatch 显式提交。
- 代码签名、供应链证明、运行时沙箱。

## 关键实现

- 组织内插件只有在同版本产物一致时才复用；同版本不同产物保留旧条目并报告冲突，要求发新版本。
- 组织内仓库如果没有 Release，使用 `https://api.github.com/repos/<org>/<repo>/tarball/<commit>`，commit SHA 固定。
- 外部仓库必须与产物来自同一个 GitHub 仓库的 `releases/download/` 路径；无法用组织仓库走外部通道。
- `GITHUB_TOKEN` 的 push 不会自动触发下游 workflow，因此两个 workflow 在成功写分支 / main 后显式 `gh workflow run ci.yml` / `pages.yml`。
- `external-plugin-pr.yml` 只写 `registry.json`，PR 标题、正文与提交信息中的 id / version 均来自校验后的 manifest。

## 验收

```bash
make check
go test -race ./...
GITHUB_TOKEN=$(gh auth token) go run ./cmd/gqy-plugin sync-org --org GQYTeam --registry /tmp/registry.json --json
```

并验证：

1. 组织内三个公开插件被识别；无 manifest 的仓库被跳过。
2. 二次同步不再改写目录。
3. 目录包含 `source_type=org`、`repository` 与 GitHubAccount 的 commit-pinned 版本。
4. 外部 URL 不是同一仓库 Release 资产时被拒绝；`GQYTeam` 来源被拒绝。
5. `external-plugin-pr.yml` 与 `sync-org-plugins.yml` 通过 actionlint。
6. `main` ruleset 保留了 1 次评审与两个 Go check，并存在 `github-actions[bot]` bypass。
7. 手动运行同步 workflow 能提交 `registry.json`，随后 CI 与 Pages 被显式触发。
